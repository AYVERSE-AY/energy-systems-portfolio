**阶段 2 关键结果**（24 时段，dt = 1 h，2026 年示意电价）：

| 方案 | 购电成本 (元) | 最大/最小并网 (kW) | 充电/放电 (kWh) | 期末储能量 (kWh) |
|---|---:|---|---|---|
| 无储能 | 943.10 | 80.0 / 26.0 | 0 / 0 | 50.00 |
| 固定规则（原） | 905.00 | 74.0 / 30.0 | 42.0 / 48.0 | 39.37 |
| 固定规则（公平） | 916.10 | 74.0 / 30.0 | 42.0 / 37.9 | 50.00 |
| MILP 优化 | **898.94** | 75.0 / 26.0 | 87.37 / 78.85 | 50.00 |

优化相对公平基准节省 **17.16 元/日（1.87 %）**；相对无储能节省 44.16 元/日（4.68 %）。
成本公式 `Σ price_t × grid_t × dt`，节省 = 公平基准成本 − 优化成本（正值为节省）。
最优解结构：谷段充满到 SOC 95% → 峰段放空至 12 kWh → 平段（22–23 时）回充至 50 kWh。

**口径说明**：原固定规则方案成本 905.00 元对应期末储能量 39.3737 kWh，与期末 50 kWh 的
公平基准及优化方案不可直接比较；节省率一律以公平基准 916.10 元计算。

### 已知的本机环境特性与对策

1. **0700 目录自锁**：受限令牌下，Python 用 mode `0o700` 创建的目录随后对本进程不可访问（`WinError 5`）。`tempfile.mkdtemp`、`ensurepip`、`pip`、pytest 的 `tmp_path` 都受影响。
   对策：`.venv/Lib/site-packages/sitecustomize.py` 把 `os.mkdir` 的目录模式统一放宽为 `0o777`。该文件在 venv 内，**不入库**；重建 venv 需重新放入。
   已用内置诊断脚本检查目录 ACL，结论 `NOT_THIS_CLASS`（ACL 正常，不是权限损坏）。

2. **C 盘空间不足**：系统盘仅剩约 30 MB，无法容纳依赖。故 venv 实体放 D 盘，项目内用链接保留 `.venv` 路径。

3. **pytest 临时目录**：默认会落在 Harness 临时目录并踩到第 1 条问题，已在 `pytest.ini` 用 `--basetemp=.pytest_tmp` 固定到项目内（已 git 忽略）。

4. **pip 输出经管道会挂起**：长时间 `pip` 调用请把输出重定向到日志文件，不要直接接管道。

5. **全局 `pip.exe` 不可用**（`D:\Scripts\pip.exe` 退出码 1）。始终使用 `python -m pip`。
